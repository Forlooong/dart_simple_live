# 弹幕与关注刷新优化

本次保留 Flutter 界面、播放器和平台连接鉴权，将四个平台的弹幕解压、协议解析及过滤放入 Rust。解码与过滤各由一个 worker 串行拥有原生句柄；原生 ACK 先发送，聊天室事件保持顺序。正常关闭等待在途操作释放内存，切房、重连、停止及规则更新均有代次检查。

## 行为变化

- 隐藏或清空屏幕弹幕后，渲染组件停止动画和清理定时任务；恢复显示不补播积压弹幕。
- 聊天最新消息、查看历史的固定快照和待显示消息分别最多 200 条、1 MiB。消息按 50 毫秒一次性合并发布；空闲不轮询。历史阅读位置保持稳定，点击“最新”回到最新队列。
- 关注查询同一轮合并执行，默认并发 4、观看时最多 2；使用轻量状态接口和同一执行环境内的短期缓存。独立系统通知任务仍按原有规则执行。
- 屏蔽规则只在版本变化时编译，普通关键词使用 UTF-16 多模式匹配。复杂规则先由 Rust 执行，无法编译的有效规则交给独立、有中断预算的 QuickJS 运行时。
- 旧无效规则保留文本并提示。规则超过数量、长度或执行预算时，暂停该规则版本的普通聊天发布，编辑规则后恢复；播放器、ACK、人数和醒目留言继续处理。

## 资源边界

单个 WebSocket 载荷最多 4 MiB；待解析输入最多 8 MiB；累计解压与输出各最多 16 MiB；压缩嵌套最多 4 层，结构嵌套最多 32 层。普通聊天过载时丢弃最旧待处理项并计数，控制事件溢出明确断开弹幕并按次数限制重连。

每次原生调用前检查队列容量，而不是把未处理数据全部发进 isolate 邮箱。规则安装最多 2,000 条、单条最多 4,096 个 UTF-16 单元、合计最多 1 MiB UTF-16 文本；匹配预算为每规则 100,000 次回溯、每批 1,000,000 次。QuickJS 设 32 MiB 内存、512 KiB 栈及引擎主动检查的 100 毫秒期限。该期限属于协作式中断，不能视为硬实时保证。

## 构建与验证

工具链固定为 Flutter 3.38.10 / Dart 3.10.9 / Rust 1.90.0。原生代码通过 Dart build hooks 打包，Android 保留 API 24 并验证 16 KiB ELF 页面对齐。macOS 验证双架构原生库；Windows、Linux 和控制台验证库实际加载；iOS 增加模拟器原生接口集成测试。

主要验证入口：

```sh
cd simple_live_core/packages/danmaku_native/rust
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
cd ../../..
dart test test/native_danmaku_test.dart test/native_danmaku_lifecycle_test.dart
dart test test/status_refresh_test.dart test/room_status_snapshot_test.dart
```

主应用和 TV 的聊天、弹幕生命周期及关注服务回归由各自 Flutter 测试运行。已有播放器恢复和通知测试必须一并通过。

## 实机功耗验证

2026-10-14 在 Windows x64 / Dart 3.10.9 上运行 `dart run tool/benchmark_danmaku.dart`，覆盖 100、1,000、5,000 条/秒与 0、10、100、1,000 条规则的 12 种组合。每组持续 2 秒，全部消息均收到，无丢弃、未解释丢失或失败。5,000 条/秒时，0、10、100、1,000 条规则的输入至回调 P95 分别为 2.27、3.31、7.60、41.78 毫秒。该短时测试使用合成普通文本和非匹配规则，只验证原生处理管线，不包含 Flutter 绘制、视频、长期稳定性或功耗；没有旧版对照，因此不能据此给出加速比例。

桌面测试及构建通过不能证明手机温度下降。设备验收需在 S20+ 及其他性能档位 Android 手机上，固定直播内容、编码、码率、亮度、音量、环境温度及放置条件，分别使用 Wi-Fi 和移动网络运行 30 分钟，对比 CPU、内存、耗电和温度。记录硬件解码状态与弹幕速率；把关闭弹幕、关闭复杂过滤作为对照组。当前没有连接可用于该实验的手机，设备功耗与降温幅度需另行实测。
